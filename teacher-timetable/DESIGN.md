# 國民中學教師課表查詢與多欄並排對照系統－設計文件

## 1. 文件目的

本文件說明「教師課表查詢與多欄並排對照系統」的功能、架構、資料格式與維護方式。本系統設計為可部署於 GitHub Pages 的純前端靜態網站，供學校快速查詢班級與教師課表。

## 2. 系統目標

- 以班級課表、教師課表 1、教師課表 2 進行三欄並排查詢與比較。
- 在班級與教師課表之間提供點選連動，減少重複選擇操作。
- 支援 CSV 匯入／匯出與本機資料持久化。
- 提供系統管理模式，保護資料匯入與系統設定。
- 可在首次開啟時，從 `data` 資料夾完成設定、教師與課表的初始化。
- 可直接部署於 GitHub Pages，不需資料庫或後端伺服器。

## 3. 系統架構

系統由瀏覽器執行，使用 HTML5、CSS3 與 Vanilla JavaScript 開發。

```text
GitHub Pages / 本機靜態網站
│
├─ index.html       頁面結構與管理介面
├─ styles.css       響應式版面、格線與色彩設計
├─ app.js           資料處理、課表渲染、互動與管理功能
└─ data/
   ├─ config.json   網站標題、節次時間、管理密碼、預設查詢值
   ├─ teachers.csv  教師資料
   └─ timetable.csv 課表資料

瀏覽器 localStorage
├─ jhs_config
├─ jhs_teachers
└─ jhs_timetable
```

### 3.1 執行流程

1. 網頁載入後讀取瀏覽器 `localStorage`。
2. 若首次執行，或教師／課表資料尚未儲存，系統讀取 `data` 資料夾的三個預設檔案。
3. 預設資料寫入 `localStorage`，並建立班級、教師查詢選單。
4. 系統渲染班級與兩位教師的週課表。
5. 後續操作優先使用 `localStorage`，不會自動覆蓋使用者已匯入或修改的資料。

## 4. 功能設計

### 4.1 三欄課表查詢

頁面上方提供三個獨立選單：

| 查詢欄位 | 顯示內容 | 用途 |
| --- | --- | --- |
| 班級查詢 | 班級課表 | 顯示科目名稱與授課教師 |
| 教師查詢 1 | 教師課表 | 顯示授課班級與科目 |
| 教師查詢 2 | 教師課表 | 供第二位教師進行並排比較 |

課表以星期一至星期五、每日第 1 至第 8 節呈現。表格具備清楚格線、交錯列底色與不同類型的標題色彩：班級課表為藍色系，教師課表為綠色系。

### 4.2 點選連動

- 點選「班級課表」的課程格，系統將該課程教師帶入「教師查詢 1」，並重新渲染教師課表。
- 點選任一「教師課表」的課程格，系統將該課程班級帶入「班級查詢」，並重新渲染班級課表。

### 4.3 節次與時間

系統可設定每日第 1 至第 8 節的上課與下課時間。課表左側的節次欄分行顯示「第 N 節」與上下課時間，便於閱讀。

### 4.4 系統管理

「系統管理」按鈕開啟密碼驗證對話框。驗證成功後才會顯示下列功能：

- 設定網頁標題
- 設定每節上下課時間
- 修改管理密碼
- 匯入／匯出設定檔
- 匯入／匯出教師與課表 CSV
- 初始化資料
- 還原範例資料與清除本機資料

預設管理密碼為 `123`。本密碼儲存在瀏覽器的 `localStorage` 與設定檔中，僅為介面控管，不可視為伺服器等級的安全機制。

### 4.5 初始化資料

系統初始化有兩種情境：

1. **首次執行**：當 `localStorage` 中沒有教師、課表或設定資料時，系統自動載入 `data/config.json`、`data/teachers.csv`、`data/timetable.csv`。
2. **手動初始化**：系統管理者按下「初始化資料」並確認後，系統以 `data` 資料夾三個檔案完整覆蓋目前的本機資料。

## 5. 資料格式

### 5.1 教師資料：`teachers.csv`

```csv
教師id,職稱,姓名,領域
88,教師,蔡珠娟,國文
```

| 欄位 | 說明 |
| --- | --- |
| 教師id | 教師唯一識別碼，須與課表的教師 id 對應 |
| 職稱 | 教師職稱 |
| 姓名 | 教師姓名 |
| 領域 | 任教領域或專長 |

### 5.2 課表資料：`timetable.csv`

```csv
流水號,班級編號,節次,科目代碼,科目名稱,教師id,教師姓名
316175,125,26,20,公民,232,謝耀瑩
```

| 欄位 | 說明 |
| --- | --- |
| 流水號 | 資料唯一流水號 |
| 班級編號 | 班級代號，例如 107、125 |
| 節次 | 雙碼節次，例如 26 為星期二第 6 節 |
| 科目代碼 | 校務系統科目代碼 |
| 科目名稱 | 顯示於班級課表的科目名稱 |
| 教師id | 授課教師識別碼 |
| 教師姓名 | 授課教師姓名，用於課表資料補充顯示 |

節次格式驗證規則為 `^[1-5][1-8]$`：第一碼為星期一至星期五，第二碼為第 1 至第 8 節。

### 5.3 設定檔：`config.json`

```json
{
  "siteTitle": "國民中學課表查詢系統",
  "adminPassword": "123",
  "periodTimes": {
    "1": { "start": "08:00", "end": "08:45" }
  }
}
```

設定檔亦可包含最近選取的 `classId`、`teacher1`、`teacher2`，供恢復預設查詢畫面使用。

## 6. 匯入、匯出與編碼

- 教師與課表匯入支援 UTF-8 與 Big5（CP950）CSV。
- 匯出 CSV 會加入 UTF-8 BOM，確保 Microsoft Excel 可正確顯示中文。
- 設定檔使用 JSON 匯入／匯出。
- CSV 內容會進行格式檢查；課表的班級、科目名稱、教師 id 與節次格式皆不可不符規則。

## 7. 資料持久化與限制

### 7.1 localStorage

使用者在網頁匯入或設定的資料儲存在該瀏覽器的 `localStorage`。不同裝置、不同瀏覽器及無痕視窗不共用資料；清除瀏覽器網站資料後，系統將再次以 `data` 預設檔初始化。

### 7.2 GitHub Pages 限制

GitHub Pages 為靜態網站，瀏覽器可讀取 `data` 檔案，但不能直接寫入 GitHub 儲存庫。因此網頁內「匯入 CSV」只會更新本機 `localStorage`，不會自動改寫 GitHub 的 `data` 資料夾。

若需更新 GitHub Pages 的預設資料，管理者應將資料匯出後，更新專案中的 `data` 三個檔案，再進行 Git 提交與推送。

## 8. 部署方式

GitHub Pages 專案路徑如下：

```text
ana202102.github.io/
└─ teacher-timetable/
   ├─ index.html
   ├─ app.js
   ├─ styles.css
   ├─ DESIGN.md
   └─ data/
```

公開網址：<https://ana202102.github.io/teacher-timetable/>

GitHub Pages 從 `main` 分支發布。部署後通常需等待數分鐘才會反映最新版本。

## 9. 維護建議

1. 更新正式課表前，先匯出現有設定、教師與課表作為備份。
2. 同步更新 `teachers.csv` 與 `timetable.csv`，避免教師 id 無法對應。
3. 修改 `data` 檔案後，請重新部署並以無痕視窗測試首次初始化結果。
4. 請避免在前端程式或公開設定檔中放置真正的帳號密碼、API Token 或個人敏感資料。
